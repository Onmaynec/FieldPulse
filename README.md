# FieldPulse

FieldPulse — диспетчеризация выездных инженеров, контроль SLA, клиентские акты и PWA с офлайн-черновиками. Репозиторий ведётся по техническому заданию PV-FSM-02. Текущая версия — **v0.7.0**. До полной приёмки по PV-FSM-02 остаются открытые пункты; см. docs/acceptance.md.

## Запуск

Требуется Docker Desktop или Docker Engine с Compose v2.

1. Создать конфигурацию из .env.example (в PowerShell: Copy-Item .env.example .env).
2. Изменить SESSION_SECRET (длинный случайный ключ), POSTGRES_PASSWORD, S3_SECRET_KEY и DEMO_PASSWORD.
3. Выполнить: docker compose up -d --build.
4. Выполнить: docker compose run --rm seed.
5. Открыть http://localhost:8000. Swagger/OpenAPI: http://localhost:8000/api/docs.

Миграции запускаются контейнером migrate до старта API и worker. Демонстрационная загрузка идемпотентна по наличию записей.

## Функции

- Клиент создаёт заявку, выбирает объект, оборудование и приоритет. Сервер связывает заявку с неизменяемым снимком SLA и отмечает возможный дубль за 24 часа.
- Диспетчер получает объяснимое ранжирование инженеров по навыку (50), смене (25), району (15) и загрузке (до 10). Допустимость проверяется повторно при назначении.
- Сроки реакции и устранения вычисляются по календарю и зоне объекта. Разрешённая пауза продлевает дедлайн устранения. Worker предупреждает за 10 минут и фиксирует уникальное событие нарушения.
- Инженер предварительно загружает задачи и затем фиксирует работы, обязательные чек-листы, материалы и фотографии без сети. IndexedDB хранит локальные UUID-операции. Повторная синхронизация не дублирует данные; при изменённой версии возникает сохраняемый конфликт.
- Клиент принимает или возвращает версионированный акт. Редакции не уничтожаются. Внутренние комментарии скрыты сервером.
- S3-совместимое хранилище SILO хранит изображения с контролем доступа. JPEG/PNG/WebP перекодируются без EXIF и с миниатюрой.

## Технологии

FastAPI / Python 3.12, SQLAlchemy, Alembic, PostgreSQL 16, S3-совместимое хранилище SILO (поддерживаемый форк MinIO), Service Worker, IndexedDB, SSE. Подписанные HttpOnly cookie, CSRF-токен, серверный RBAC. JSON API с документацией OpenAPI 3.x.

Демо-набор: 120 зданий, 600 единиц оборудования, 45 инженеров, 15 SLA-политик, 2000 заявок. Тестовые данные моделируют рабочий процесс; они не доказывают производительность.

## v0.7.0 — Incident Response & Scale Validation

Развил контроль состояния SLA-worker до самостоятельного журнала инцидентов и подключил воспроизводимую проверку SQL-запросов на больших наборах.

- **Независимый сервис `monitor`:** раз в 15 секунд проверяет сохранённое состояние worker и записывает открытие/закрытие инцидентов, даже когда сам worker остановлен.
- **История с подтверждениями:** серверный журнал `operational_incidents`, защищённые API для персонала и кнопка «Подтвердить» в аналитике. Подтверждение не закрывает и не скрывает сбой.
- **Необязательные уведомления:** только при настройке `ALERT_WEBHOOK_URL` отдельный HTTPS-webhook получает события открытия и восстановления без данных заявок и пользователей. Доставка с повторными попытками сохраняется в `incident_deliveries`.
- **Проверка наблюдения:** Docker healthcheck отдельно для `monitor` и `worker`. Если PostgreSQL недоступен, внешний webhook тоже может не сработать — для промышленной среды нужен дополнительный независимый мониторинг инфраструктуры.
- **Профили SQL:** на выделенных CI-контейнерах выполняются тесты запросов на 50/200 тыс. синтетических заявок с `EXPLAIN ANALYZE`, затем транзакция откатывается. Измерения нельзя приравнивать к производственной нагрузке.
- **Индекс `ix_ticket_created_seek`:** на базе из 202 000 строк исправил обнаруженное медленное сканирование при сортировке по дате создания; фактический план PostgreSQL теперь использует B-Tree.
- **Миграция `0005_operational_incidents`:** таблицы истории, очереди доставки, heartbeat наблюдения и индекс поиска.

Сначала создайте и проверьте резервную копию PostgreSQL и медиа. Обновление — `docker compose up -d --build`; Alembic применит новую ревизию.

## v0.6.0 — Search Performance & Observability

Переработал работу с глубокими страницами заявок, дашборд и диагностику SLA-worker.

- **Новый курсорный API:** `GET /api/v1/tickets/seek` поддерживает сортировку по созданию, дедлайну или приоритету без SQL OFFSET. Курсор подписан, действует один час и привязан к пользователю и текущим фильтрам.
- **Два режима реестра:** нумерованная выдача с общим количеством записей и быстрый курсорный просмотр без полного подсчёта на каждом шаге.
- **Полный дашборд:** `GET /api/v1/board/summary` считает статусы и сроки по всем доступным заявкам в PostgreSQL, а не по первым 500.
- **Мониторинг worker:** в БД записываются проходы, последний успех/ошибка, длительность, количество SLA-событий; Docker healthcheck и виджет аналитики обновляют фактическое состояние.
- **Запросы PostgreSQL:** добавлены BTREE-индексы по срокам; при доступных правах создаются pg_trgm и GIN-индексы для поиска.
- **Реальные планы:** `scripts/search_plan.py` и артефакт CI с EXPLAIN ANALYZE. Бенчмарки 50/200 тысяч строк доступны как отдельный opt-in тест на стенде, но без результатов не считаются пройденными.
- **Миграция:** `0004_worker_observability` после резервной копии применяется через `docker compose up -d --build`.

Подробности: [заметки v0.6.0](docs/releases/v0.6.0.md), [протокол замеров](docs/benchmarks/v0.6.0-search.md) и [эксплуатация](docs/operations.md).

## v0.5.0 — Registry & Operations

Реестр больше не ограничен последними 500 заявками. Фильтры, поиск, сортировка, подсчёт записей и пагинация выполняются в PostgreSQL с учётом серверных прав доступа.

- Новый `GET /api/v1/tickets/search`: параметры `page`, `page_size` (10–100), `q`, `status`, `priority`, `sort` и `active`. Ответ содержит `items`, `total`, `page`, `page_size`, `pages`.
- До 12 **сохранённых представлений на пользователя** — персональные наборы фильтров, доступные после повторного входа.
- Таблица реестра загружает только выбранную страницу по 20, 50 или 100 записей, а не весь реестр в браузер.
- Инженерная PWA загружает активные назначения постранично и больше не зависит от глобального списка первых 500 обращений.
- Операционные показатели: время последнего события, возраст старейшей записи mock inbox, незакрытые P1 и обращения без исполнителя.
- Схема PostgreSQL обновляется миграцией `0003_ticket_views`, включающей таблицу представлений и индексы поиска.

Чтобы обновить установку, сначала создайте резервную копию БД и фотографий, затем выполните `docker compose up -d --build`. Отдельная процедура переноса данных не требуется: Compose запускает миграцию перед API.

Ограничения: OFFSET может замедляться на глубоких страницах, а `ILIKE` пока работает без полнотекстового индекса. Метрики mock inbox **не доказывают работоспособность фонового worker или внешнюю доставку**.

Подробности: [заметки v0.5.0](docs/releases/v0.5.0.md).

- **Раздел «Администрирование»** — загрузка CSV в браузере с dry-run, новые редакции SLA, навыки и смены инженеров, журнал административных изменений.

- **Локальная приватность** — отдельные IndexedDB для каждого инженера, перенос относящихся к нему черновиков V1 в Chrome/Edge.
- **Миграция 0002** — отпечатки событий и отдельный AdminAudit.
- **Тестирование** — новый сквозной сценарий на PostgreSQL + S3: изоляция клиентов, назначение, принятие, 2 фотографии, повтор sync и возврат акта. Нагрузка в 1000 фотографий в сутки пока не измерялась.

## Импорт CSV

Начальная загрузка из CSV выполняется в разделе «Администрирование» (права администратора, файл до 2 МиБ) либо через CLI: python -m app.import_csv sites|assets|contracts <file>. Схемы — docs/csv-import.md. Поддерживается предварительная проверка и откат файла при ошибке.

## Проверка

Установить: pip install -r requirements-dev.txt. Запустить pytest -q, node --check public/app.js. GitHub Actions проверяет код, образ, развёртывание и сквозной сценарий. ## Хранилище в Docker Compose

Исторические образы MinIO перестали скачиваться из Docker Hub, а Quay отвечает 401 на анонимное скачивание. Поэтому для воспроизводимого запуска используется поддерживаемый форк MinIO — SILO. API использует протокол S3 без зависимости от бренда хранилища. Это отличие от буквального варианта инфраструктуры ТЗ.

## Обновление с v0.1.0

Перед обновлением сохраните дамп PostgreSQL и копию S3-объектов. Команда docker compose up -d --build автоматически применит миграции вплоть до 0005. Существующие демонстрационные данные не перезаписываются. В Chrome/Edge при первом повторном входе инженера принадлежащие ему офлайн-записи старой версии переносятся в раздельное хранилище. Очистка данных сайта уничтожит несинхронизированные записи.

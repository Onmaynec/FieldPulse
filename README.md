# FieldPulse

FieldPulse — диспетчеризация выездных инженеров, контроль SLA, клиентские акты и PWA с офлайн-черновиками. Репозиторий ведётся по техническому заданию PV-FSM-02. Текущая версия — **v0.8.0**. До полной приёмки по PV-FSM-02 остаются открытые пункты; см. `docs/acceptance.md`.

## Запуск

Требуется Docker Desktop или Docker Engine с Compose v2.

1. Создать конфигурацию из `.env.example` (в PowerShell: `Copy-Item .env.example .env`).
2. Изменить `SESSION_SECRET` (длинный случайный ключ), `POSTGRES_PASSWORD`, `S3_SECRET_KEY` и `DEMO_PASSWORD`.
3. Выполнить: `docker compose up -d --build`.
4. Выполнить: `docker compose run --rm seed`.
5. Открыть http://localhost:8000. Swagger/OpenAPI: http://localhost:8000/api/docs.

Миграции запускаются контейнером `migrate` до старта API и worker. Демонстрационная загрузка идемпотентна по наличию записей.

## Функции

- Клиент создаёт заявку, выбирает объект, оборудование и приоритет. Сервер связывает заявку с неизменяемым снимком SLA и отмечает возможный дубль за 24 часа.
- Диспетчер получает объяснимое ранжирование инженеров по навыку (50), смене (25), району (15) и загрузке (до 10). Допустимость проверяется повторно при назначении.
- Сроки реакции и устранения вычисляются по календарю и зоне объекта. Разрешённая пауза продлевает дедлайн устранения. Worker предупреждает за 10 минут и фиксирует уникальное событие нарушения.
- Инженер предварительно загружает задачи и затем фиксирует работы, обязательные чек-листы, материалы и фотографии без сети. IndexedDB хранит локальные UUID-операции. Повторная синхронизация не дублирует данные; при изменённой версии возникает сохраняемый конфликт.
- Мобильный модуль хранит ограниченную локальную идентичность инженера, чтобы открыть ранее загруженные карточки после перезапуска браузера без сети. Пароль и сессионный токен в локальный профиль не записываются. Браузер может запросить постоянное хранилище, но решение принимает сам браузер.
- Обновление кеша карточек выполняется одной транзакцией IndexedDB: если запись нового набора не проходит по квоте, прежний целый снимок не очищается.
- Клиент принимает или возвращает версионированный акт. Редакции не уничтожаются. Внутренние комментарии скрыты сервером.
- S3-совместимое хранилище SILO хранит изображения с контролем доступа. При штатной ошибке загрузки миниатюры исходный объект удаляется; при откате транзакции записи компенсирующее удаление убирает уже загруженные объекты. Аварийное завершение процесса всё ещё может оставить сиротский объект.
- Отдельный SLA monitor регистрирует сбои worker, историю восстановления и операторские подтверждения. Внешний webhook включается только конфигурацией.
- Полный архив содержит PostgreSQL custom dump и все объекты `tickets/` с SHA-256 манифестом. Создание требует явного подтверждения окна обслуживания; восстановление разрешено только в чистую изолированную базу и пустой bucket.

## v0.8.0 — Recovery & Data Integrity

- **Restore drill:** отдельный Compose-проект с собственными PostgreSQL и SILO; проверка всех таблиц, Alembic revision, ролей, связей вложений и SHA-256 каждого S3-объекта.
- **Проверка повреждённого архива:** усечённый ZIP должен отклоняться до начала восстановления.
- **Конкурентные операции:** параллельное назначение/отмена заявок, UUID мобильной синхронизации, возвраты актов, параллельные SLA-worker.
- **Компенсация загрузки фото:** частично загруженная пара оригинал/миниатюра очищается при ошибке; при откате записи удаляются все уже загруженные изображения.
- **PWA:** локальная идентичность переживает закрытие браузера, кеш карточек заменяется атомарно, очередь продолжает отправку даже если обновить список заданий не удалось.
- **Суточный профиль:** `scripts/load_profile.py` умеет распределять 200 заявок и 1000 фотографий на заданный период и записывать p50/p95, объём JPEG и параметры среды. Наличие режима не означает, что 24-часовой прогон уже выполнен.

Подробности: [релиз v0.8.0](docs/releases/v0.8.0.md), [протокол восстановления](docs/benchmarks/v0.8.0-recovery.md), [эксплуатация](docs/operations.md).

## Импорт CSV

Начальная загрузка из CSV выполняется в разделе «Администрирование» (права администратора, файл до 2 МиБ) либо через CLI: `python -m app.import_csv sites|assets|contracts <file>`. Схемы — `docs/csv-import.md`. Поддерживается предварительная проверка и откат файла при ошибке.

## Проверка

Установить: `pip install -r requirements-dev.txt`. Запустить `pytest -q`, `node --check public/app.js`. GitHub Actions проверяет код, образ, развёртывание, PWA, конкурентные сценарии и отдельный восстановительный контур. Полный backup/restore drill публикует артефакт `fieldpulse-v08-recovery-drill`.

## Хранилище в Docker Compose

Исторические образы MinIO перестали скачиваться из Docker Hub, а Quay отвечает 401 на анонимное скачивание. Поэтому для воспроизводимого запуска используется поддерживаемый форк MinIO — SILO. API использует протокол S3 без зависимости от бренда хранилища. Это отличие от буквального варианта инфраструктуры ТЗ.

## Обновление

Перед обновлением сохраните резервную копию PostgreSQL и S3. Команда `docker compose up -d --build` автоматически применит миграции. Существующие демонстрационные данные не перезаписываются. Очистка данных сайта уничтожит несинхронизированные записи инженера.

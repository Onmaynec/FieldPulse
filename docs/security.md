# Безопасность и роли

Клиент видит только собственные объекты и их заявки/акты. Чужие идентификаторы должны давать 404 без метаданных. Инженер получает только назначенные задачи и не может назначать себя. Диспетчер управляет назначениями, паузами и триажем. Руководитель получает аналитику и право решения спорных актов. Администратор не имеет API редактирования событий аудита.

Подписанная сессия передаётся в HttpOnly SameSite=Lax cookie; для POST требуется CSRF-токен из отдельной cookie. Пароли используют salted scrypt. Вложения ограничены 10 МиБ, декодируются как JPEG/PNG/WebP, повторно кодируются в JPEG без EXIF; чтение проходит проверку доступа. CSP блокирует сторонние скрипты. Перед production необходимы HTTPS и COOKIE_SECURE=1.

## Перед запуском на публичном сервере

Необходимы ограничение частоты входа, полноценное управление сессиями, внешнее тестирование безопасности, ревизия секретов и TLS. Начальные демо-аккаунты использовать исключительно локально. Скрытый элемент интерфейса не является контролем доступа: все разрешения проверяются в API.

Ошибочные попытки входа по сочетанию IP и email ограничены пятью за 15 минут (HTTP 429). Идемпотентность создания заявок использует PostgreSQL advisory transaction lock; параллельные назначения одному инженеру сериализуются блокировкой его строки.

После прекращения распространения контейнерных образов MinIO стандартный Compose использует поддерживаемый S3-совместимый форк SILO (pgsty/silo, фиксированная версия от 12.11.2026). Имена сервиса и переменных MINIO_* сохранены для совместимости.

## Офлайн-данные v0.8.0

В localStorage хранится только минимальная идентичность инженера `id/name/role`, необходимая для повторного открытия локальных карточек после перезапуска браузера. Пароль, session cookie и токены не сохраняются. Серверная авторизация остаётся обязательной для любой синхронизации и чтения новых данных.

Очередь работ, чек-листы и фотографии находятся в IndexedDB. Приложение не шифрует их на диске: браузерный профиль и устройство должны быть защищены средствами ОС, а общий профиль браузера нельзя считать безопасным рабочим местом. Запрос persistent storage — только подсказка браузеру; браузер может отказать, а пользователь может удалить локальные данные.

## Резервные копии

Архив содержит рабочую базу и фотографии, поэтому доступ к нему равен доступу к данным приложения. Не публикуйте ZIP в репозитории или общедоступном CI-артефакте; ограничивайте доступ, шифруйте носитель и задавайте срок хранения. `--maintenance-confirmed` не останавливает внешние writers: оператор обязан обеспечить окно обслуживания. Restore отказывается работать поверх существующей прикладной схемы и требует отдельную пустую БД и пустой bucket.

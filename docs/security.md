# Безопасность и роли

Клиент видит только собственные объекты и их заявки/акты. Чужие идентификаторы должны давать 404 без метаданных. Инженер получает только назначенные задачи и не может назначать себя. Диспетчер управляет назначениями, паузами и триажем. Руководитель получает аналитику и право решения спорных актов. Администратор не имеет API редактирования событий аудита.

Подписанная сессия передаётся в HttpOnly SameSite=Lax cookie; для POST требуется CSRF-токен из отдельной cookie. Пароли используют salted scrypt. Вложения ограничены 10 МиБ, декодируются как JPEG/PNG/WebP, повторно кодируются в JPEG без EXIF; чтение проходит проверку доступа. CSP блокирует сторонние скрипты. Перед production необходимы HTTPS и COOKIE_SECURE=1.

## Перед запуском на публичном сервере

Необходимы ограничение частоты входа, полноценное управление сессиями, внешнее тестирование безопасности, ревизия секретов и TLS. Начальные демо-аккаунты использовать исключительно локально. Скрытый элемент интерфейса не является контролем доступа: все разрешения проверяются в API.


Ошибочные попытки входа по сочетанию IP и email ограничены пятью за 15 минут (HTTP 429). Идемпотентность создания заявок использует PostgreSQL advisory transaction lock; параллельные назначения одному инженеру сериализуются блокировкой его строки.


После прекращения распространения контейнерных образов MinIO стандартный Compose использует поддерживаемый S3-совместимый форк SILO (pgsty/silo, фиксированная версия от 12.11.2026). Имена сервиса и переменных MINIO_* сохранены для совместимости. При строгой приёмке требования о конкретном MinIO-контейнере потребуется согласовать этот инфраструктурный компромисс.

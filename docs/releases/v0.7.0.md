# FieldPulse v0.7.0 — Incident Response & Scale Validation

В предыдущем релизе добавил heartbeat для SLA-worker, но не было процесса, который заметит остановку этого worker, когда сам worker не может записать ошибку. В v0.7.0 добавил независимый контур наблюдения, журнал инцидентов и опциональные внешние уведомления. Отдельно расширил замеры PostgreSQL за пределы 2000 записей.

## Независимое обнаружение отказов

- Новый сервис `monitor` запускается отдельным процессом Compose, проверяет состояние SLA-worker каждые 15 секунд и сохраняет инциденты в PostgreSQL.
- Если ошибка зафиксирована после последнего успешного цикла — регистрируется `error`. Если успешного прохода нет более 75 секунд — `stale`. При первоначальном отсутствии heartbeat действует 90-секундный допуск.
- После подтверждённого восстановления инцидент закрывается. Отдельный уникальный индекс допускает только один активный инцидент на источник, история не уничтожается.
- Добавлены `monitor_cycles` и отдельный Docker healthcheck для самого monitor. Если база данных недоступна, монитор не может работать — этот предел явно сохраняется.

## Экран инцидентов

- В аналитике появилась история с состояниями, временем обнаружения и восстановления. Есть список активных и завершённых инцидентов, число неподтверждённых, состояние наблюдения и счётчики внешней доставки.
- Диспетчер, менеджер и администратор могут подтвердить просмотр через защищённый POST API. Подтверждение не подавляет оповещение и не отмечает поломку устранённой.
- API: `GET /api/v1/operations/incidents`, `GET /api/v1/operations/summary` и `POST /api/v1/operations/incidents/{id}/ack`. Роль и CSRF проверяются сервером.

## HTTPS-webhook по желанию оператора

- При явно настроенном `ALERT_WEBHOOK_URL` события открытия и восстановления записываются в `incident_deliveries`, после чего monitor пытается их отправить.
- Ответ 2xx отмечает отправку; ошибка оставляет запись с временем следующей попытки и классом ошибки, без чувствительных текстов.
- Retry с увеличением интервала до 900 секунд; идентификаторы событий неизменны. Получателю необходима дедупликация, поскольку при сетевом сбое возможны повторы.
- В payload нет описаний заявок, имён, email, текстов исключений и секрета URL. Простой HTTP и редиректы не поддерживаются.
- Без настройки внешнего endpoint локальные инциденты работают. `outbox` SLA-уведомлений по-прежнему не отправляется автоматически.

## Проверка реального масштаба

- В CI добавлена отдельная база и job `large-search-benchmark`. Скрипт `search_plan.py` генерирует временные 50 000 и 200 000 заявок, собирает `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`, p50/p95 и использованные индексы и откатывает операции.
- Выполнение реальных прогонов подтверждается отдельными JSON-артефактами. Цифры без их проверки не приводятся как факты.
- Обычные Python-тесты дополнены открытием/повтором/восстановлением инцидента, правами ролей, CSRF, приватностью payload и retry. Браузерный сценарий проверяет подтверждение реального инцидента на изолированном Compose.

## Совместимость и границы

- Миграция Alembic `0005_operational_incidents`, новый контейнер monitor, необязательная переменная окружения `ALERT_WEBHOOK_URL`. API и PWA мобильных заданий не менялись.
- Для установки нужна проверенная резервная копия PostgreSQL и S3, затем `docker compose up -d --build`. Демо-среду в Интернет без смены секретов не выставлять.
- Монитор не заменяет внешние алерты при потере базы/хоста. Система не доставляет автоматически сообщения из старого mock inbox.
- Длительные 24-часовые испытания с тяжёлыми изображениями, 48 часов offline и полный disaster recovery пока не объявлены пройденными.

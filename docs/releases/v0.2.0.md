# FieldPulse v0.2.0 — Управление и надёжность

Основное обновление после v0.1.0: интерфейс для администратора, более строгая доставка офлайн-событий и расчёт фактической рабочей реакции по SLA.

## Администрирование

- В интерфейсе появился отдельный раздел для администратора.
- CSV объектов, оборудования и договоров загружается из браузера. Проверка без записи доступна до импорта, ошибки откатывают весь файл. Максимальный размер — 2 МиБ.
- Настройка инженера: набор компетенций electrical/hvac/low_voltage, район и доступность. Назначение смены отклоняется при пересечении с уже известной.
- Редактор договора создаёт новую SLA-политику, связывает её с объектом и приоритетом. Старые заявки сохраняют прежний снимок.
- Изменения справочников регистрируются в журнале AdminAudit.

## Офлайн-синхронизация

- Worklog получает хеш содержимого операции. Повтор UUID с другим содержимым больше не считается дубликатом.
- Несколько событий от одного исходного снимка можно отправить одним пакетом без искусственного конфликта между ними.
- Сторонняя правка заявки или отмена по-прежнему требует ручного разрешения конфликта.
- Обязательные данные материалов проверяются на непустое название, диапазон и числовую конечность.
- У каждого инженера собственный IndexedDB. Из старой V1-базы мигрируют связанные с его учётной записью записи без удаления чужих.

## SLA и аналитика

- p50/p95 реакции теперь учитывают только рабочие интервалы календаря объекта.
- Политики версионируются и не переписывают прошлые SLA-обязательства.
- Демо-наполнение скорректировано так, чтобы исторические открытые задания не блокировали весь подбор новых исполнителей.

## Проверки

- Unit/API: запрет доступа к чужим актам и администрированию, валидация импорта, неизменность SLA, UUID-повторы с изменённым payload, последовательный пакет офлайн-действий, p50/p95 через выходные.
- Compose smoke: две организации, клиентская заявка, назначение и принятие инженером, две фотографии в S3, повтор синхронизации, отклонение акта и создание второй редакции.
- Автоматические проверки Python, JavaScript, Docker-образа, PostgreSQL и миграций.

## Ограничения

Релиз не является финальной сдачей PV-FSM-02. Не проводились измерения 200 заявок / 1000 фотографий за день, полноформатный отказоустойчивый прогон, контроль 48 часов офлайна на мобильном устройстве и браузерные E2E по всем ролям. Политика доступа, отмены и конфликты покрыты частичными автоматическими сценариями, но отдельный аудит безопасности ещё требуется.

Текущий Compose использует S3-совместимый SILO вместо недоступного анонимного контейнерного образа MinIO. Отступление от буквального технологического стека ТЗ зафиксировано.

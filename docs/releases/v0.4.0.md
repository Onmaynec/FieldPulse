# FieldPulse v0.4.0 — Visual Overhaul

Это визуальный релиз. Переработал систему оформления, навигацию и основные рабочие экраны. Серверный API остался совместимым с v0.3.0: не добавлял миграций и не менял авторизацию.

## Общая дизайн-система

- Полностью переписал `public/styles.css`, сделал единые цветовые токены для светлой и тёмной темы, новую систему интервалов, поверхностей, границ, карточек, кнопок, таблиц и форм.
- Тёмная тема переключается без перезагрузки и сохраняется в браузере. Для длинных таблиц добавил обычный и компактный режим.
- Подготовил интерфейсы для размеров от 320 до 2560 пикселей. Клавиатурный фокус заметен, а при системной настройке `prefers-reduced-motion` анимации минимальны.

## Экран входа и навигация

- Полностью переработал компоновку авторизации, брендовый блок и демонстрационные роли.
- Обновил боковую панель: единые SVG-иконки вместо разнородных символов, выделение текущего раздела с `aria-current`.
- В верхней панели есть быстрый переход к поиску заявок (`Ctrl+K` / `Cmd+K`) и переключение тем.
- Мобильная навигация открывается отдельным меню с затемняющей подложкой и закрывается клавишей Escape.

## Операционный обзор и заявки

- Дашборд дополнен блоком ближайших SLA-дедлайнов, сортированных по дате, с пометками «Срок близко» и «Просрочена». Используются только реальные записи и даты.
- Реестр: полнотекстовый поиск по загруженным записям, фильтры по статусу и приоритету, три сортировки, страницы по 20 строк и компактная плотность.
- Таблица показывает фактические сроки, исполнительскую принадлежность и состояние SLA. Открытие заявки доступно с клавиатуры через отдельную кнопку.

## Карточка заявки, фотографии и акты

- Карточка стала рабочим окном с блоками SLA, срока реакции и решения, историей событий, исполнителем, документами и записями о работах.
- Добавил галерею миниатюр. Изображения загружаются через защищённый маршрут API с проверкой доступа, а не по открытой ссылке в S3.
- Переработал акты: сводные показатели по редакциям, явно выделенные статусы согласования/возврата, понятные действия просмотра.

## Инженер, аналитика и администрирование

- Инженер видит офлайн/онлайн-состояние, последнюю загрузку карточек, локальные задания, очередь отправки и конфликты. При пакетной синхронизации показывается номер обрабатываемой группы.
- Раздел объектов поддерживает поиск по названию, городу, району и часовому поясу. Ограничение отображения первых 60 объектов убрано.
- Аналитика и административные формы используют общую визуальную систему, без добавления фальшивых KPI и демонстрационных значений в статистике.

## Проверка

- Сохранил существующий API/DB/S3/Docker/Playwright offline CI.
- Добавил `scripts/visual_e2e.py`: вход через пять ролей, смена тем, фильтры, мобильная навигация, контроль ширины и скриншоты в двух разрешениях.
- Браузерные тесты не заменяют ручную оценку графики и accessibility-аудит; приёмка на реальных устройствах остаётся отдельным этапом.

## Известные границы

- Пагинация и фильтрация реестра работают по последним 500 заявкам из API, а не по всей серверной БД.
- Визуальные скриншоты создаются автоматически, но утверждённая baseline-картинка для пиксельного сравнения ещё не добавлена.
- Реальные фотографии, таблицы и имена в приложении отображаются из вашей базы; UI не добавляет искусственных данных.
- Остаточные задачи полного PV-FSM-02 перечислены в `docs/acceptance.md` и issue #3.

## Следующий этап

В v0.5.0 планирую продолжить продуктовую работу после визуального обновления: серверная пагинация и фильтрация больших реестров, улучшенные сохранённые представления и усиление эксплуатационного мониторинга. Реализованными в v0.4.0 эти пункты не считаются.

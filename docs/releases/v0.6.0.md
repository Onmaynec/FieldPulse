# FieldPulse v0.6.0 — Search Performance & Observability

Развил v0.5.0, в которой поиск выполнялся сервером, но глубокие страницы всё ещё использовали SQL OFFSET, а дашборд — только последние 500 заявок.

## Курсорная выдача

- Добавил `GET /api/v1/tickets/seek`: LIMIT и keyset без OFFSET, сортировки по дате, дедлайну и приоритету.
- Возвращает `items`, `next_cursor`, `has_more`. Список ролей и фильтры применяются непосредственно в SQL.
- Курсор подписан и действует час; привязан к пользователю, поиску, статусу, приоритету, сортировке, active и размеру страницы.
- Ошибочный, чужой или изменённый контекст возвращает 422. Курсор не содержит персональных данных.
- В реестре два переключаемых режима: нумерованные страницы и быстрый курсорный просмотр. Сохранённые представления продолжили работать. Старые API не удалены.

## Полный дашборд

- `GET /api/v1/board/summary` считает статусы, открытые/закрытые, неназначенные, P1, просроченные и близкие сроки по всем разрешённым роли заявкам.
- Ближайшие шесть и последние семь обращений отбираются в PostgreSQL. Активные паузы SLA не трактуются как текущие просрочки устранения.
- Сводка не полагается на ограничение предыдущего клиента в 500 заявок.

## Наблюдаемость SLA worker

- Новая таблица `worker_cycles` хранит отметки последнего успеха, ошибки, длительности, число циклов и созданных SLA-событий.
- Сведения фиксируются в отдельной транзакции после реального коммита SLA-прохода. Тексты исключений и данные заявок в heartbeat не записываются.
- Добавил защищённый `/reports/worker-health`, состояния `healthy` / `stale` / `error` / `unknown`, порог 75 секунд и Docker healthcheck.
- В аналитике — отдельная карточка состояния с обновлением каждые 20 секунд.
- SLA-сканер теперь выбирает только заявки с приближающимися сроками реакции или устранения вместо полной блокировки всех открытых.

## PostgreSQL и воспроизводимость

- Добавил BTREE индексы для SLA и keyset; `pg_trgm` и GIN-индексы пытаются установиться лишь при доступных правах расширения.
- `scripts/search_plan.py` получает реальные `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` с p50/p95 и планом. По умолчанию ничего не записывает. Режимы 50/200 тысяч строк требуют явного разрешения и отдельного стенда.
- Новые Python-тесты проверяют три сортировки, целостность/привязку курсоров, данные разных ролей и логику остановки/восстановления worker. Браузерный сценарий проверяет переходы вперёд/назад и фильтры.
- Существующие API, офлайн-очередь, S3, акты и визуальная система v0.4.0 сохранены.

## Границы релиза

Keyset не создаёт неизменяемый снимок БД — изменения порядка заявок между запросами могут отразиться на выдаче. Ускорение поиска зависит от плана PostgreSQL; наличие индекса ещё не доказывает его использование. Бенчмарки 50/200 тысяч строк нельзя считать выполненными до отдельного прогона и проверки артефактов. Внешняя доставка сообщений и полноценный мониторинг alerts пока не реализованы.

Для обновления: проверенная резервная копия PostgreSQL/S3, затем `docker compose up -d --build`. Применяется миграция `0004_worker_observability`. Полная приёмка PV-FSM-02 по 48-часовому offline, реальной суточной нагрузке и disaster recovery остаётся открытой.

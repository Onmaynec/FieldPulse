# FieldPulse v0.5.0 — Registry & Operations

После визуальной модернизации v0.4.0 убрал основное ограничение реестра: ранее браузер загружал 500 заявок и фильтровал только их. Для рабочей системы с тысячами обращений это было неприемлемо.

## Серверный реестр

- Реализовал `GET /api/v1/tickets/search` с `page`, `page_size` (10–100), `q` (до 100 символов), `status`, `priority`, `sort` и `active`.
- Сервер возвращает точное количество доступных заявок, число страниц и только записи запрошенной страницы. Поиск охватывает номер, описание, объект, оборудование и назначенного инженера.
- Права клиента по организации и инженера по назначению проверяются **до** поиска и подсчёта результатов. Сортировки по дате создания, ближайшему SLA и приоритету фиксированы на сервере.
- Добавлены составные индексы по организации/дате, инженеру/дате и статусу/сроку.
- Старый `GET /tickets` сохранён для совместимости с предыдущими версиями клиентов.

## Сохранённые представления

- Новая сущность `ticket_views` хранит персональные фильтры в PostgreSQL.
- Каждый пользователь может создать до 12 именованных наборов (поиск, статус, приоритет, сортировка, число строк), применить их снова или удалить.
- Чужие представления не видны и не удаляются. Для изменения требуется CSRF; одинаковые названия обрабатываются явным конфликтом.

## Мобильная PWA и диагностика

- Инженерская PWA обновляет кеш по всему активному объёму своих заявок постранично. Существующая очередь офлайн-действий и структура IndexedDB остаются совместимыми.
- Отчёт операций дополнен открытыми P1, неназначенными обращениями, временем последнего события и возрастом старейшего сообщения mock inbox. Это не мониторинг heartbeat worker.

## Проверка

- 4 дополнительных серверных теста для пагинации, фильтров, изоляции организаций, списка и удаления персональных представлений, ошибок валидации и операционных полей.
- Новый Playwright `scripts/registry_e2e.py` проверяет реестр на настоящей демо-базе с более чем 2000 заявками и цикл сохранить → открыть → применить → удалить представление.
- Сохранил существующие проверки Python, Docker, PostgreSQL/S3, офлайн-синхронизации, визуальных ролей и нагрузки.

## Ограничения

- Глубокие страницы используют SQL OFFSET; для сотен тысяч заявок потребуется курсорная пагинация.
- Текстовый поиск по подстроке использует ILIKE, специализированного полнотекстового индекса пока нет.
- Обзорная панель по-прежнему показывает последние 500 заявок; её серверная агрегация — отдельная задача.
- Полная приёмка PV-FSM-02 (48 часов офлайна, нагрузка с реальными файлами, восстановление после сбоя) не объявлена завершённой.

Стандартное обновление: после резервной копии выполняется `docker compose up -d --build`. Контейнер `migrate` применит `0003_ticket_views`.

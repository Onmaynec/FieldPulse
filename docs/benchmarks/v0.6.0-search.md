# FieldPulse v0.6.0 — замеры PostgreSQL

Скрипт `python -m scripts.search_plan` использует реальные запросы SQLAlchemy и PostgreSQL `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`.

Проверяются сортировки newest, deadline, priority: первая страница, глубокая OFFSET-страница и keyset на сопоставимой позиции. Дополнительно измеряется поиск подстроки. JSON содержит фактический размер датасета, глубину страницы, PostgreSQL version, число CPU, наличие pg_trgm, p50/p95 замеров, planning/execution time и узлы плана с индексами/буферами.

## Что подтверждает CI

Автоматический тест работает на демонстрационных **2000 заявках**, запускает пять повторений и сохраняет JSON в артефакте `fieldpulse-v06-postgres-plans`. Не стоит цитировать числовые показатели без соответствующего артефакта и его окружения.

## Дополнительные 50 000 и 200 000 строк

На отдельном тестовом экземпляре выполняются:

    docker compose exec -T api python -m scripts.search_plan --generate 50000 --allow-demo-write --expected-min 50000 --repeats 7 --output /tmp/search-50k.json
    docker compose exec -T api python -m scripts.search_plan --generate 200000 --allow-demo-write --expected-min 200000 --repeats 7 --output /tmp/search-200k.json

Вставки производятся в некоммитнутой транзакции и откатываются, но реально используют WAL, CPU, RAM и статистику планировщика. Не выполнять на продакшене.

**Эти опциональные сценарии не считаются пройденными, пока не сформированы и проверены их артефакты.** При сравнении учитывайте холодный/прогретый кеш и одинаковое оборудование. Наличие GIN pg_trgm не гарантирует его использование для OR-поиска через JOIN.

## Приёмочные тесты

AT-01 — unit календаря. AT-02 — тест назначения без навыка. AT-03 — неизменность события после правки глобальной SLA-политики. AT-04 — API и S3 проходят сквозной прогон с двумя фото, но нет ручного 48-часового протокола отключения сети в браузере. AT-05 — тест повторного UUID. AT-06 — тест конфликта после отмены. AT-07 — автоматический запрет доступа клиента Б к заявке, объекту и акту клиента А. AT-08 — проверка неполного списка. AT-09 — повторный запуск worker без дублей, но не полноценный процессный restart-test. AT-10 — возврат акта с созданием новой редакции. AT-11 — пока нет нагрузочного отчёта. AT-12 — нет итогового сквозного протокола сверки timeline и отчёта.

## Блокирующие задачи до полной сдачи

- Расширенное администрирование календарей, обратимые изменения и полноценные права по отделам (базовый интерфейс и импорт CSV добавлены).
- Промышленная защита окружения, шифрование офлайн-данных, мониторинг, дополнительный security-review.
- PostgreSQL/S3 smoke добавлен; остаются браузерные E2E, 48-часовой offline-протокол, нагрузка и стресс-тест параллельных транзакций.
- Нагрузочные испытания, p50/p95 с конфигурацией железа и планом исправления узких мест.
- Подтверждённый протокол всех AT, включая 48 часов офлайна.


Дополнительное усиление: включён лимит ошибочных попыток аутентификации, а создание заявок с повторяющимся ключом защищено PostgreSQL advisory-lock.


## Статус v0.2.0

Ветка версии прошла тесты API и Docker Compose с реальным S3 (два фото); это не заменяет финальную приёмку AT-01…AT-12. В частности, AT-11 и AT-12 остаются открытыми.

## Дополнения v0.3.0

- Добавлены серверные маршруты reports/sites, reports/tickets/{id}/reconcile, reports/operations, ограниченные диспетчерскими ролями.
- PostgreSQL+S3 backup с манифестом SHA-256 и scanner для необслуживаемых объектов.
- Playwright offline E2E добавлен в CI, но 48-часовой натурный тест остаётся незакрытым.
- Параметризованный генератор нагрузки создан; AT-11 не считается пройденным до замеров на согласованном железе.
- Полноценный тест восстановления всей системы и расширенный аудит безопасности остаются открытыми.

## Статус v0.4.0 — Visual Overhaul

- Переработаны CSS/HTML и клиентское приложение без новых серверных таблиц и миграций.
- Сохраняются светлая/тёмная темы и режим плотности реестра; все выборы остаются локальными на браузере.
- На дашборде отображаются ближайшие дедлайны **из загруженных заявок**, а не все сроки во всей БД: API списка ограничен 500 записями.
- Реестр имеет пользовательскую пагинацию по загруженному набору, фильтры и сортировку. Это **не серверная пагинация**, поэтому полноценная работа с тысячами записей требует отдельной разработки.
- Карточка показывает только авторизованные вложения и записи через существующий API.
- Добавлены браузерные проверки ролей, скриншоты разных ширин, переключение тем и тест отсутствия горизонтального переполнения.
- 48-часовой офлайн-тест, длительная нагрузка, независимый disaster-recovery drill и внешняя проверка безопасности по-прежнему требуют отдельной приёмки.


## Статус v0.5.0

- Добавлен `GET /api/v1/tickets/search` со строгими фильтрами, пагинацией и глобальным `total` по доступным текущей роли заявкам.
- Доступность заявок в поиске и сохранённых представлениях проверяется только сервером. Межорганизационная изоляция не зависит от текстового запроса или названия представления.
- Персональные наборы фильтров хранятся в отдельной таблице `ticket_views`; лимит 12 на пользователя, уникальное имя в пределах аккаунта.
- Кеширование активных задач PWA инженер получает со всех страниц, без обрезки до 500 глобальных записей.
- Мониторинг предоставляет возраст сохранённых сообщений и последнюю активность БД, но не heartbeat worker. Мониторинг процессов и внешней доставки ещё открыт.
- Добавлены серверные тесты отказов и браузерный сценарий с более чем 2000 заявками.

Открытые требования: 48-часовая натурная офлайн-приёмка, независимая сверка SLA, суточная нагрузка и disaster recovery drill. Новый реестр не означает закрытия всего ТЗ.

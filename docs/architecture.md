# Архитектура FieldPulse

## Компоненты

API на FastAPI реализует серверную проверку прав, статусы, заявки, договоры, SLA, синхронизацию и акты. PostgreSQL — транзакционный источник истины. MinIO — закрытое хранилище фотографий, отдаваемых только через проверяющее права API. Worker раз в 15 секунд догоняет дедлайны и заносит события с уникальными ключами в журнал и mock inbox. PWA хранит оболочку в Service Worker, а рабочие карточки и очередь действий — в IndexedDB.

## Основные сущности

Organizations → Sites → Assets. Для сайта хранится Contract с календарём и набором SLA-политик. Ticket содержит объект, оборудование, исполнителя, статус, версию, дедлайны и снимок политики на момент создания. Event фиксирует события append-only на уровне API. Worklog содержит UUID действия, server_at, client_at, материалы и чек-лист. Attachment имеет checksum, владельца и приватный ключ хранилища. Act хранит номер редакции, статус и решение клиента.

## Конкуренция

При смене статуса и назначения используется SELECT FOR UPDATE и проверка ожидаемой версии. Для синхронизации действует уникальное ограничение (engineer_id, action_uuid). Конфликт возвращается как отдельный результат без перезаписи. Время хранится в UTC, календарь рассчитывается по зоне объекта. Изменение глобальной политики SLA не меняет уже созданный снимок в заявке.

SSE передаёт событие доски без закрытых данных. Для чтения подробностей клиент использует авторизованный API. Фактический срок реакции определяется моментом принятия инженером, а не моментом назначения.

## Компромиссы

Загрузка в MinIO и запись транзакции PostgreSQL не являются единой атомарной операцией: после прерывания возможны файлы-сироты. Удаление таких файлов и расширенный аудит БД — задачи следующих этапов. Уникальные ключи worker защищают от повторов после перезапуска. Тесты SQLite не заменяют параллельные тесты PostgreSQL.
